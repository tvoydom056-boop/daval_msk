# AGENTS.md - правила для ИИ-ассистентов (Claude, Codex) и для нас двоих

Проект daval_msk: два сайта под ключ, «Летопись» (страницы памяти) и «Повод» (сайты-подарки). В репозитории исходные макеты на HTML/CSS/JS и отдельные прототипы в `v3/`, план и отчёт. Актуальный интерфейс «Повода» в `v3/povod/` на Vite, backend и отправки заявки в нём нет.

## Где искать решения

Читать по порядку, только нужные разделы:

1. [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) - стек, модули, кто какие папки ведёт, поток данных, контракт заявки, проверки и лимиты, открытые решения.
2. [PLAN.md](PLAN.md) - продукт, цены, бюджет, роли, этапы, что решить вдвоём (раздел 10). По продукту и ценам главнее он.
3. [HANDOFF.md](HANDOFF.md) - текущее состояние и следующие шаги.
4. [README.md](README.md) - как открыть макеты, где какие файлы.

Если решения нет ни в одном из файлов, не придумывать его молча: выбрать вариант «по умолчанию» из таблицы открытых решений ARCHITECTURE.md (раздел 9) и написать об этом в отчёте или PR.

## Что уже есть и как это переиспользовать

- **Актуальный «Повод»** находится в `v3/povod/`: содержимое в `src/data.js`, маршруты и форма в `src/main.js`, секции в `src/scenes/`. Запуск и проверка в README этой папки. `povod/` сохраняет прежнюю статику: её тексты в `povod/data.js`, лендинги собирает `povod/app.js`, HTML - тонкие оболочки с `data-occasion`.
- **«Летопись»**: вся страница в `letopis/index.html`, интерактив (древо, главы, слайдер, QR) в `letopis/app.js`. Данные древа отделены от раскладки `layout()`.
- **Места под фото и видео** помечены атрибутом `data-slot`. Кнопка «Слоты медиа» показывает их на странице. Новое место под медиа в макете тоже подписывать `data-slot`.
- **При переносе в Astro** брать вёрстку и скрипты из макета секциями, а не писать заново. Таблица соответствий - ARCHITECTURE.md, раздел 3.
- **Одностраничные версии прежней статики для показа ссылкой** собирает только `build_artifacts.py`; Vite-проект `v3/povod/` он не собирает. Руками `letopis/artifact.html` и `povod/artifact.html` не править (они в `.gitignore`).
- **PDF-отчёт** в `report/` собирается скриптом, руками не правится.
- **Фото** в `*/assets/img/` сгенерированы, люди вымышленные. Менять только по задаче.
- Шрифты: «Летопись» - Literata; «Повод» - Onest, Caveat только для рукописных писем. Без иконок-стрелок и круглых значков на кнопках и карточках.

## Команды, которые есть в проекте

В корне нет `package.json`, общего линтера и CI. В `v3/povod/` есть npm-команды и отдельный браузерный QA-скрипт. Не писать, что «тесты прошли», без фактического запуска нужной проверки.

| Что | Команда | Что нужно |
|---|---|---|
| Актуальный «Повод» | Из `v3/povod/`: `npm ci`, `npm run dev`; открыть http://127.0.0.1:5174/ | Node.js, npm |
| Собрать и посмотреть «Повод» v3 | Из `v3/povod/`: `npm run build`, затем `npm run preview`; открыть http://127.0.0.1:4174/ | Node.js, npm |
| Подготовить адаптивные фото «Повода» v3 | Из корня: `python codex/v3/prepare_povod_images.py`; затем пересобрать `v3/povod/` | Python, Pillow; JPEG сохраняются, обновляются WebP и `src/image-sizes.json` |
| Проверить «Повод» v3 в браузере | Из корня: `node codex/v3/check_povod_clear.mjs --url http://127.0.0.1:4174/ --playwright-module "<путь-к-playwright>"` | Установленные Playwright и Edge; вместо пути можно `PLAYWRIGHT_MODULE_PATH`, параметры в `v3/povod/README.md` |
| Открыть макеты | `python -m http.server 8765` из корня репозитория, затем http://localhost:8765/letopis/ и http://localhost:8765/povod/ | Python 3 |
| Собрать версии для показа ссылкой | `python build_artifacts.py` | Python 3 |
| Снять скриншоты для отчёта | `python report/capture_screenshots.py` при запущенном сервере на 8765 | `pip install playwright pillow`, `playwright install chromium` |
| Собрать PDF-отчёт | `python report/build_report.py` (с проверкой страниц) или `python report/build_report.py --no-render` (без неё) | `pip install reportlab pillow`, для проверки страниц ещё `pymupdf` |

Макеты дополнительно проверяются визуально в браузере на ширине 1440 и 375 px: пройти интерактив и посмотреть консоль. Браузерный QA-скрипт v3 не заменяет просмотр скриншотов.

## Как работаем: ветки и короткие правки

- Перед началом: `git pull` на `main`, затем своя ветка. В `main` напрямую не коммитим, только через Pull Request.
- Имя ветки латиницей через дефис по направлению из ARCHITECTURE.md раздел 4: `site/<что>`, `content/<что>`, `api/<что>`, `schema/<что>`, `infra/<что>`, `docs/<что>`, `fix/<что>`. Пример: `api/request-form`.
- Одна ветка = одна задача. Не смешивать в одном PR вёрстку, схему и документацию.
- PR маленький: такой, чтобы второй участник прочитал его за 10-15 минут. Большую задачу делить на несколько PR.
- Свои папки правим свободно. Чужие - только по договорённости. `schema/` меняем отдельным PR, который смотрят оба. Ревьюер каждого PR - другой участник.
- Коммиты по-русски, коротко, что сделано: «Форма заявки: проверка полей на сервере». Как в истории репозитория.
- Делать ровно то, о чём задача. Замеченные по пути проблемы перечислить в PR или отчёте, не исправлять молча.

## Перед PR

1. Изменённые страницы открыты в браузере на 1440 и 375 px, интерактив пройден, в консоли нет ошибок, горизонтальной прокрутки нет.
2. Если есть команды проверки для изменённой части, они запущены, результат написан в PR. Если команды нет, так и написать: «проверено вручную, автопроверки нет».
3. Цены, пакеты и сроки совпадают с PLAN.md. Если правили цены, обновлён PLAN.md в том же PR.
4. Изменили содержимое прежней статики - запущен `python build_artifacts.py`; для `v3/povod/` запущен `npm run build` из его папки. Изменили то, что попадает в отчёт (цены, макеты, слоты) - в PR написано, что PDF устарел или пересобран. Текущий PDF новый интерфейс v3 не покрывает.
5. В изменённых файлах нет длинного и среднего тире (U+2014, U+2013), только обычный дефис «-», в том числе в диапазонах: 1-6.
6. Нет секретов, паролей, токенов, cookies, профилей браузера, клиентских данных.
7. HANDOFF.md обновлён, если изменилось состояние проекта (что сделано, что выложено, следующий шаг).
8. В описании PR: что сделано, как проверено, что не проверено.

## Обязательные правила

- **Секреты и данные клиентов.** Репозиторий публичный. Токен Telegram-бота, пароли, ключи хостинга и `.env` в git не попадают. Клиентские `page.json`, медиа и хэши паролей живут на сервере, не здесь (ARCHITECTURE.md раздел 4). В примерах только вымышленные люди.
- **Приватные ссылки.** Пока не решён пункт 4 раздела 9 ARCHITECTURE.md, новые приватные ссылки и абсолютные пути с личных компьютеров в файлы репозитория не добавлять.
- **Не выдавать вымысел за факт.** Никаких придуманных отзывов, клиентов, числа заказов, реальных ФИО и адресов. Цены пока тестовые. Демо-форма пишет, что это макет.
- **Деликатность «Летописи».** Никаких акций, таймеров, ярких скидок и давления. Тон спокойный, без шуток и эмодзи. Оживление фото и голос умершего только по явной просьбе семьи (PLAN.md раздел 9).
- **Персональные данные.** Хранятся на серверах в РФ (152-ФЗ). Пароль приватной страницы проверяется на сервере, а не только скрывается от поиска.
- **Проверка ввода на сервере** для всего, что приходит снаружи. Правила и лимиты - ARCHITECTURE.md раздел 7.
- **Проверить результат до сдачи.** Код запустить и пройти действие пользователя, вёрстку открыть в браузере. Сдавать не «код написан», а «работает, проверено так-то».

## Отчёт после задачи
